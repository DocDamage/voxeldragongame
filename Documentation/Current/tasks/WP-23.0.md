# WP-23.0 — Rest-of-world readiness and travel/save contract

**Status:** COMPLETE on September 19, 2026. This is an inventory and contract
slice, not a region implementation.

## Objective

Inspect the supplied real content and current owner graph, distinguish source
presence from validated Unreal readiness, select one evidence-backed production
order, and define the minimum cross-region travel/save behavior that later
children must prove.

## Acceptance

- Record whether each named dragon source exists and whether its rig/profile is
  validated in Unreal PIE.
- Name plausible supplied environment/character content for every regional
  child without certifying uninspected suitability.
- Identify exact per-child blockers instead of treating one missing asset as a
  full-project block.
- Select one first eligible child based on content readiness and integration
  risk.
- Define travel, arrival, return, failure recovery, and persistence ownership;
  do not implement an empty full-world framework.

## Result

PASS. `py -3.12 tools/wp23_readiness_inventory.py` verified that all ten named
dragon source GLTFs exist in the supplied dragon archive. Only Verdance and
Jadefang currently have validated Unreal rig profiles and live-PIE evidence.
WP-23.1 and WP-23.2 are therefore packet-ready; all new-dragon children remain
blocked on their individual rig/profile proof and region-specific content fit.

The selected first eligible child is **WP-23.2 Jade Peaks closure** because it
reuses the verified `L_JadePeaks`, Jadefang, palace, disciple, Mirror Step, and
Schema 4 baseline, while the supplied palace archive also contains real ruler
characters. See [WP23_READINESS.md](../WP23_READINESS.md) and
`Saved/Diagnostics/WP23_readiness_inventory.json`.

## Boundary

No archive was imported, no new dragon was enabled, no schema was changed, and
no region was claimed complete. WP-23.2 must perform its own bounded intake,
compile, native tests, focused PIE, visual QA, travel/return, and save-recovery
proof.
